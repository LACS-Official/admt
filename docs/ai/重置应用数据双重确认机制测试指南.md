# 重置应用数据双重确认机制测试指南

## 功能概述

为"重置应用数据"按钮实现了双重确认机制，以防止用户误操作导致数据丢失。

## 实现的功能

### 1. 双重确认流程
- **第一次点击**：显示第一个确认弹窗，说明重置操作的后果
- **第一次确认**：点击"确认重置"后，显示第二个更严格的确认弹窗
- **第二次确认**：点击"重置"按钮后，执行实际的重置操作

### 2. 重置操作内容
- 撤销所有隐私政策同意
- 清除本地激活码数据
- 清除保留的用户配置
- 清除所有localStorage数据
- 应用自动退出并重启

## 测试步骤

### 前置条件
1. 确保应用已正常启动
2. 确保已有一些用户数据（如已同意隐私政策、已激活等）

### 测试用例1：完整的双重确认流程

#### 步骤：
1. 打开应用设置页面
2. 找到"隐私政策管理面板"
3. 滚动到"重置应用数据"部分
4. 点击"重置应用数据"按钮

#### 预期结果：
- 显示第一个确认弹窗
- 弹窗标题为"确认重置应用数据"
- 弹窗内容列出重置操作的后果
- 有"取消"和"确认重置"两个按钮

#### 继续步骤：
5. 点击"确认重置"按钮

#### 预期结果：
- 第一个弹窗关闭
- 显示第二个确认弹窗
- 弹窗标题为"最终确认重置"
- 弹窗内容更加严厉，强调操作不可撤销
- 有"取消"和"重置"两个按钮

#### 继续步骤：
6. 点击"重置"按钮

#### 预期结果：
- 弹窗关闭
- 控制台输出重置操作日志
- 应用自动退出
- 下次启动时显示欢迎页面

### 测试用例2：第一次取消操作

#### 步骤：
1. 点击"重置应用数据"按钮
2. 在第一个确认弹窗中点击"取消"

#### 预期结果：
- 弹窗关闭
- 没有执行任何重置操作
- 应用状态保持不变

### 测试用例3：第二次取消操作

#### 步骤：
1. 点击"重置应用数据"按钮
2. 在第一个确认弹窗中点击"确认重置"
3. 在第二个确认弹窗中点击"取消"

#### 预期结果：
- 弹窗关闭
- 没有执行任何重置操作
- 应用状态保持不变

### 测试用例4：验证数据清除完整性

#### 步骤：
1. 在执行重置前，记录以下数据：
   - localStorage中的所有键值对
   - 隐私政策同意状态
   - 激活码状态
   - 用户配置信息
2. 执行完整的重置流程
3. 重新启动应用后检查上述数据

#### 预期结果：
- 所有localStorage数据被清除
- 隐私政策同意状态被撤销
- 激活码数据被清除
- 用户配置被重置
- 应用显示首次使用流程

## 验证要点

### UI/UX验证
- [ ] 第一个确认弹窗样式正确，警告信息清晰
- [ ] 第二个确认弹窗样式更加醒目，使用红色警告色调
- [ ] 按钮文字准确（"取消"、"确认重置"、"重置"）
- [ ] 弹窗可以通过ESC键或点击遮罩层关闭

### 功能验证
- [ ] 双重确认机制正常工作
- [ ] 取消操作在任何阶段都能正常工作
- [ ] 重置操作能完全清除所有相关数据
- [ ] 应用能正常退出和重启
- [ ] 重启后显示欢迎页面

### 错误处理验证
- [ ] 如果重启失败，应用能正常退出
- [ ] 如果某些数据清除失败，不影响其他数据的清除
- [ ] 错误信息能正确记录到控制台

## 注意事项

1. **数据备份**：在测试前请备份重要数据，因为重置操作是不可逆的
2. **测试环境**：建议在开发环境中进行测试
3. **日志监控**：测试时请打开开发者工具查看控制台日志
4. **完整测试**：每次修改代码后都应该重新测试完整流程

## 已知限制

1. 重置操作依赖于Tauri的process插件，在某些环境下可能无法正常工作
2. 如果localStorage访问受限，部分数据可能无法清除
3. 网络相关的缓存数据可能需要额外的清理步骤
