# 开发版与发行版版本/公告检测功能差异分析报告

## 问题概述

开发版能够正确检测并显示动态版本信息，而发行版却只能返回并显示固定的demo数据。经过深入分析，发现了以下关键差异点。

## 核心问题分析

### 1. 环境变量配置差异

**开发版配置：**
- 使用 `import.meta.env.DEV = true`
- 动态API端点配置
- 完整的环境变量支持

**发行版配置：**
- 使用 `import.meta.env.DEV = false`
- 固化的API端点配置
- 环境变量可能未正确传递

### 2. API端点配置问题

**位置：** `src/config/api.ts`

```typescript
// 当前实现存在问题
export const getApiBaseUrl = () => {
  // 在生产环境中直接使用BASE_URL，不区分开发和生产
  return API_CONFIG.BASE_URL;
};
```

**问题：** 发行版构建时，环境变量可能未正确注入，导致使用默认值。

### 3. 版本检查服务实现差异

**位置：** `src/services/versionService.ts`

```typescript
private getApiConfig() {
  const isDev = import.meta.env.DEV;
  const baseUrl = getApiBaseUrl();
  
  console.log(`🔧 版本检查API配置:`, {
    isDev,
    baseUrl,
    mode: import.meta.env.MODE,
    softwareId: API_CONFIG.SOFTWARE_ID
  });
  
  return {
    baseUrl,
    endpoints: {
      version: `${baseUrl}/app/software/id/${API_CONFIG.SOFTWARE_ID}/versions/latest`,
      announcement: `${baseUrl}/app/software/id/${API_CONFIG.SOFTWARE_ID}/announcements`
    }
  };
}
```

**问题：** 发行版中 `API_CONFIG.SOFTWARE_ID` 可能使用默认值1，而不是实际的软件ID。

### 4. Tauri后端版本检查差异

**位置：** `src-tauri/src/version.rs`

```rust
#[command]
pub async fn check_for_updates() -> Result<UpdateCheckResult, String> {
    let current_version = env!("CARGO_PKG_VERSION");
    
    // API端点配置存在硬编码问题
    let api_url = if cfg!(debug_assertions) {
        "http://localhost:3001/api/version/check"
    } else {
        "https://api-g.lacs.cc/api/version/check"  // 固定端点
    };
    
    // ...
}
```

**问题：** 发行版使用固定的API端点，可能与前端配置不一致。

### 5. 安全配置初始化问题

**位置：** `src/config/securityConfig.ts`

```typescript
private async initializeWithDefaults(): Promise<void> {
  const defaultConfig: SecurityConfig = {
    api_base_url: 'https://api-g.lacs.cc/',
    // ...
    software_id: 1  // 硬编码的默认值
  }
  
  // 标记为降级模式
  (window as any).__ADMT_FALLBACK_CONFIG__ = true;
}
```

**问题：** 发行版可能频繁使用降级配置，导致使用错误的软件ID。

## 解决方案

### 1. 修复环境变量配置

创建生产环境专用的环境变量文件：

```bash
# .env.production
VITE_API_BASE_URL=https://api-g.lacs.cc
VITE_SOFTWARE_ID=1
VITE_APP_VERSION=1.0.0
VITE_ENABLE_SIGNATURE=true
VITE_ENABLE_STRICT_USER_AGENT=true
VITE_SIGNATURE_SECRET=your_production_secret
```

### 2. 修复API配置逻辑

更新 `src/config/api.ts`：

```typescript
export const getApiBaseUrl = () => {
  const isDev = import.meta.env.DEV;
  const envBaseUrl = getEnvVar('VITE_API_BASE_URL');
  
  if (envBaseUrl) {
    return envBaseUrl;
  }
  
  // 降级逻辑
  return isDev ? API_CONFIG.DEV_BASE_URL : API_CONFIG.BASE_URL;
};

export const getSoftwareId = () => {
  const envSoftwareId = getEnvNumber('VITE_SOFTWARE_ID', 0);
  if (envSoftwareId > 0) {
    return envSoftwareId;
  }
  
  // 发行版必须有明确的软件ID
  if (!import.meta.env.DEV) {
    console.error('❌ 生产环境缺少VITE_SOFTWARE_ID配置');
    throw new Error('Production build requires VITE_SOFTWARE_ID');
  }
  
  return API_CONFIG.SOFTWARE_ID;
};
```

### 3. 统一前后端API配置

更新 `src-tauri/src/version.rs`：

```rust
#[command]
pub async fn check_for_updates() -> Result<UpdateCheckResult, String> {
    let current_version = env!("CARGO_PKG_VERSION");
    
    // 从前端获取API配置，而不是硬编码
    let api_url = if cfg!(debug_assertions) {
        "http://localhost:3001/api/version/check"
    } else {
        // 使用环境变量或配置文件
        std::env::var("API_BASE_URL")
            .unwrap_or_else(|_| "https://api-g.lacs.cc".to_string())
            + "/api/version/check"
    };
    
    // ...
}
```

### 4. 增强错误处理和日志

更新版本检查服务：

```typescript
async checkForUpdates(): Promise<VersionCheckResult> {
  try {
    const config = this.getApiConfig();
    
    // 验证配置完整性
    if (!config.baseUrl || config.baseUrl.includes('example.com')) {
      throw new Error('Invalid API configuration detected');
    }
    
    if (API_CONFIG.SOFTWARE_ID <= 0) {
      throw new Error('Invalid software ID configuration');
    }
    
    console.log(`🔍 版本检查配置验证通过:`, {
      baseUrl: config.baseUrl,
      softwareId: API_CONFIG.SOFTWARE_ID,
      isDev: import.meta.env.DEV,
      mode: import.meta.env.MODE
    });
    
    // 继续执行版本检查...
  } catch (error) {
    console.error('❌ 版本检查配置验证失败:', error);
    // 返回错误结果而不是静默失败
    return {
      hasUpdate: false,
      needsUpdate: false,
      isForceUpdate: false,
      currentVersion: await this.getCurrentVersion(),
      error: `配置错误: ${error.message}`,
      message: '版本检查配置无效'
    };
  }
}
```

### 5. 构建流程优化

更新 `package.json` 构建脚本：

```json
{
  "scripts": {
    "build:dev": "vite build --mode development",
    "build:prod": "vite build --mode production",
    "tauri:build:prod": "tauri build --config-path tauri.prod.conf.json",
    "prebuild": "npm run clean && npm run validate-env"
  }
}
```

添加环境验证脚本：

```javascript
// scripts/validate-env.js
const requiredEnvVars = [
  'VITE_API_BASE_URL',
  'VITE_SOFTWARE_ID',
  'VITE_APP_VERSION'
];

for (const envVar of requiredEnvVars) {
  if (!process.env[envVar]) {
    console.error(`❌ Missing required environment variable: ${envVar}`);
    process.exit(1);
  }
}

console.log('✅ Environment variables validation passed');
```
