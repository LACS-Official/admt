# ADMT 项目安全性缺陷审计报告

本报告针对 ADMT 项目（Tauri 桌面端应用）进行了全面的安全性审计，识别出多处潜在的安全缺陷与设计隐患。Tauri 应用由于桥接了前端 Webview 与后端 Rust 系统级 API，若不对 IPC 通信及输入进行严格限制，极易导致前端 XSS 漏洞升级为宿主机乃至连接设备的远程代码执行（RCE）。

---

## 1. 严重漏洞 (Critical / High)

### 1.1 非 Windows 平台命令注入漏洞
*   **代码位置**：[`execute_script_in_new_window`](file:///e:/tauri/admt/src-tauri/src/commands/app.rs#L128-L241)
*   **缺陷描述**：
    在非 Windows 系统下，命令执行采用 `sh -c` 的方式：
    ```rust
    let mut cmd = Command::new("sh");
    cmd.args(&["-c", &script_str]);
    ```
    `script_str` 为规范化后的脚本路径。如果传入的脚本路径包含 shell 元字符（如 `;`、`&`、`|`、`$` 或反引号），或者文件名本身可控，将导致在宿主机上执行任意 shell 命令。
*   **修复建议**：
    避免使用 `sh -c` 解释执行。如果只需要运行特定脚本，应直接使用 `Command::new(script_path)` 并传递参数数组，或者使用 Tauri 的 `shell` 插件官方机制。

### 1.2 Android 设备端 root 命令注入漏洞
*   **代码位置**：[`backup_partition`](file:///e:/tauri/admt/src-tauri/src/commands/system.rs#L661-L715)
*   **缺陷描述**：
    程序通过字符串格式化构建命令，在 Android 设备上使用 `su -c` 权限执行 `dd`：
    ```rust
    let dd_cmd = format!(
        "su -c 'dd if=/dev/block/by-name/{} of={}'",
        partition, temp_device_path
    );
    ```
    参数 `partition` 直接由前端传入且未做过滤。若前端传入 `boot'; reboot; #` 这样的恶意分区名称，由于闭合了单引号，导致在 Android 设备（若已 Root）以 root 权限执行任意 shell 命令。
*   **修复建议**：
    - 在后端验证 `partition` 是否仅包含安全的字母、数字和下划线。
    - 避免直接将参数拼接进 `su -c` 字符串，可考虑将 `dd` 及其参数拆分为单独的参数包：`su -c "dd" "if=..." "of=..."`，或者在执行前使用正则白名单对 `partition` 参数进行严格校验。

### 1.3 目录遍历与任意文件操作风险
*   **代码位置**：[`fs.rs`](file:///e:/tauri/admt/src-tauri/src/commands/fs.rs) 及 [`download.rs`](file:///e:/tauri/admt/src-tauri/src/commands/download.rs)
*   **缺陷描述**：
    1.  **任意文件删除**：[`delete_file`](file:///e:/tauri/admt/src-tauri/src/commands/fs.rs#L52-L63) 允许删除前端传入的任意 `path`，无任何范围限制。
    2.  **任意文件读写**：[`read_json_file`](file:///e:/tauri/admt/src-tauri/src/commands/fs.rs#L66-L85) 和 [`write_json_file`](file:///e:/tauri/admt/src-tauri/src/commands/fs.rs#L88-L112) 允许对本地任意路径读写 JSON，未对路径范围进行边界限制（沙箱化）。
    3.  **下载路径穿越**：[`download_apk`](file:///e:/tauri/admt/src-tauri/src/commands/download.rs#L21-L69) 和 [`download_file`](file:///e:/tauri/admt/src-tauri/src/commands/download.rs#L123-L182) 接收前端传入的 `file_name` 并使用 `join` 拼接。在 Rust 中，若 `file_name` 包含 `../`，或者本身是一个绝对路径，会导致下载文件写入到任意系统目录（如系统自启动目录、系统库目录），导致远程代码执行（RCE）。
    4.  **资源路径读取逃逸**：[`get_resource_path`](file:///e:/tauri/admt/src-tauri/src/commands/fs.rs#L115) 拼接相对路径。如果 `path` 是一个绝对路径，Rust 的 `join` 行为会直接丢弃前缀，使 `get_resource_path` 指向该绝对路径，导致 [`read_resource_file`](file:///e:/tauri/admt/src-tauri/src/commands/fs.rs#L195) 可以读取宿主机的任意二进制文件。
*   **修复建议**：
    - 对所有传入的文件路径进行规范化（`canonicalize`），并校验其是否包含在指定的目标基准目录下（如 `$APP_DATA` 或 `$DOWNLOAD`）。
    - 限制 `file_name` 不得包含路径分隔符（如 `/` 或 `\`），禁止 `..`。

### 1.4 不安全的 SSL/TLS 证书校验（容易遭受中间人攻击）
*   **代码位置**：[`HttpRangeReader::new`](file:///e:/tauri/admt/src-tauri/src/commands/rom.rs#L34-L37)
*   **缺陷描述**：
    ```rust
    let client = Client::builder()
        .danger_accept_invalid_certs(true)
        .build()
    ```
    此处明确配置了危险的 `danger_accept_invalid_certs(true)`，禁用了 SSL 证书验证。当用户在线解析或提取固件包时，同一局域网内的攻击者可以通过 ARP 欺骗或 DNS 劫持发起中间人攻击（MITM），向应用喂送伪造的响应、破坏固件提取逻辑，甚至通过格式解析漏洞进行远程代码攻击。
*   **修复建议**：
    移除 `.danger_accept_invalid_certs(true)`。如果部分测试环境使用自签名证书，应仅在调试模式（`cfg!(debug_assertions)`）下启用，生产环境必须强制校验证书。

## 2. 中危隐患与设计缺陷 (Medium)

### 2.1 硬编码 API 敏感密钥
*   **代码位置**：[`get_security_config`](file:///e:/tauri/admt/src-tauri/src/commands/config.rs#L170-L194)
*   **缺陷描述**：
    代码中硬编码了应用与服务端的签名秘钥和配置：
    - `app_secret`: `"wjgj_2024_secure_app_secret_key_for_user_behavior_stats"`
    - `signature_secret`: `"signature_secret_2024_wanjiguanjia_user_behavior_api_protection"`
    由于桌面端应用分发给所有用户，任何攻击者都能通过简单的逆向工具直接提取这些硬编码的密钥，从而伪造 API 签名，绕过服务端防刷限制。
*   **修复建议**：
    - 客户端应用无法绝对安全地存储密钥。建议引入动态凭证分发，或将受保护的请求代理到安全的服务端，避免在客户端进行签名。

### 2.2 不安全的 Content Security Policy (CSP)
*   **代码位置**：[`tauri.conf.json`](file:///e:/tauri/admt/src-tauri/tauri.conf.json#L107-L109)
*   **缺陷描述**：
    ```json
    "security": {
      "csp": "... script-src 'self' 'unsafe-inline' 'unsafe-eval'; ..."
    }
    ```
    允许 `'unsafe-eval'` 和 `'unsafe-inline'` 会使 CSP 的防护作用大打折扣。若前端页面存在输入未过滤引入的 XSS 攻击，攻击者可以直接执行任意构造的代码，并结合开放的 Tauri IPC 命令接管宿主机。
*   **修复建议**：
    在生产发布前，移除 `'unsafe-eval'`，并尽量使用 nonce 或 hash 替代 `'unsafe-inline'`，确保前端无法动态执行不可信字符串。

### 2.3 前端授权校验旁路（激活绕过）
*   **代码位置**：[`activationService.ts`](file:///e:/tauri/admt/src/services/activationService.ts)
*   **缺陷描述**：
    激活服务被 Stub 化（模拟实现），所有接口如 `checkActivationStatus` 和 `isActivated` 均无条件返回 `true`（"2099-12-31 永久授权"）。这虽然方便了开发或分发，但也意味着软件的付费/授权控制已被彻底绕过。
*   **修复建议**：
    若要商业化发布，必须移除 Stub 逻辑，在 Rust 后端进行高强度的本地证书签名校验和动态云端二次验证。

## 3. 低危与防御性编码缺陷 (Low)

### 3.1 冗余的死代码与未校验的输入
*   **代码位置**：[`is_valid_serial` 在 utils.rs](file:///e:/tauri/admt/src-tauri/src/utils.rs#L340-L345)
*   **缺陷描述**：
    `utils.rs` 定义了用于校验设备序列号合法性的函数 `is_valid_serial`，但由于从未被调用而被标记为 `#[allow(dead_code)]`。所有接收 `serial` 的 Rust 命令均直接信任前端输入。
*   **修复建议**：
    在所有调用 ADB 命令前，对传入的 `serial` 进行 `is_valid_serial` 校验，防止潜在的非预期输入引发的行为异常。

### 3.2 参数拆分拼接的脆弱逻辑
*   **代码位置**：[`execute_adb_command`](file:///e:/tauri/admt/src-tauri/src/adb/command/adb_command_runer.rs#L134)
*   **缺陷描述**：
    ```rust
    let string_args: Vec<String> = args
        .iter()
        .map(|s| s.as_str())
        .collect::<Vec<&str>>()
        .join(" ")
        .split_whitespace()
        .map(|s| s.to_string())
        .collect();
    ```
    将前端传入的参数数组先用空格连接，再通过空白字符切分。这种做法不仅是一个严重的业务 bug（导致所有包含空格的参数如路径被粉碎），也导致参数结构在非预期空格下发生突变，存在参数注入风险。
*   **修复建议**：
    直接保留前端传入的 `args: Vec<String>`，不要做 `.join(" ").split_whitespace()` 变换。

### 3.3 敏感系统接口过度暴露
*   **代码位置**：[`terminate_process`](file:///e:/tauri/admt/src-tauri/src/commands/app.rs#L245)
*   **缺陷描述**：
    应用无条件向前端暴露了 `terminate_process` 接口，该接口允许指定任意 `process_id` 进行结束（对 Windows 执行 `taskkill`，非 Windows 执行 `kill -9`）。这允许前端任意终止操作系统级别的关键进程，导致系统崩溃或拒绝服务攻击（DoS）。
*   **修复建议**：
    除非绝对必要，否则不应暴露允许终止任意 PID 的命令。若只需要终止自己拉起的子进程（如 adb 或 scrcpy），应在 Rust 后端保存这些子进程的句柄，仅允许终止由本程序拉起的特定子进程。
